## Static checks

- **Root preparation is separate from file projection.** `project_tree_adapter.rs:213-345` creates the checked active-provider index once, then uses borrowed per-provider Java/Kotlin sets, a bounded set of built-in group buckets, exact-path unsupported-priority lookup and exact-path deduplication. The new preparation work is proportional to selected root occurrences with ordered-set/map factors; it does not scan the file inventory for each root. It inherits the existing active-provider model validation cost, rather than establishing a new bound for all upstream model shapes. `required_presence_paths` (`:155-176`) builds an explicit deduplicated requirement set and performs no probing.
- **Inventory checks avoid a cross-product with all roots.** `:436-551` builds borrowed root/path sets and visits each captured entry once. Java-capable classification walks that entry's ancestors and queries the package-root set (`:486-493`). This is dependent on path depth and ordered-path comparison cost, rather than an `entries × every root` scan. Absolute-path normalization allocates one temporary normalized path per check (`:634-647`); captured paths and output facts are owned separately as required by the existing projection boundary.
- **Ancestor inference does not repeatedly traverse shared prefixes.** `:555-580` keeps a borrowed completed-ancestor set and stops at the first previously visited ancestor. It allocates additional file facts only for missing inventory rows that are actual planned directory roots or the module directory. It neither creates a full duplicate physical inventory nor performs filesystem I/O. The unchanged projection and presence hierarchy checks also stop at completed/proven directory ancestors (`project_tree.rs:271-295,306-321`; `project_tree_facts.rs:699-725`).
- **Java buffers remain shared and parsing is conservatively bounded.** Input bytes are `Arc<[u8]>` (`:369-372`); adaptation borrows their slice and moves discovered name facts without copying the source buffer. The parser rejects inputs above 8 MiB before UTF-8 checking or lexing (`java_class_facts.rs:114-129`) and bounds declarations/depth to 16,384/512. The adapter accounts for every eligible input at or below that per-file limit before parsing it (`:499-507`), including inputs that later fail. It never increments beyond the 32 MiB aggregate allowance; the remaining-budget subtraction is therefore safe. Oversized buffers reach the parser's constant-work size rejection, and exhausted aggregate capacity creates an ordinary-file fallback without parsing that buffer. Later eligible smaller inputs may use remaining capacity. Duplicate-name sets borrow names, and offset checks reference the original UTF-8 slice (`:509-531`).
- **Index cloning is outside the file loop.** `:591-614` copies the prepared module, provider index and encounter facts once per adaptation. There is no provider-index clone or rebuild per captured file. Provider resolution uses indexed exact/ancestor roots (`project_tree_facts.rs:518-528`) rather than scanning every provider root. Resolution allocates the matching candidate list; its cost depends on actual overlapping matches, which should be represented in later measured cases.
- **Output size remains honest.** The 32 MiB constant bounds aggregate parser input work, not total module RSS or the host's retained source buffers. Paths, presence maps, diagnostics, class names and tree nodes require additional memory proportional to their represented data. The unchanged facts-aware projection intentionally walks each root's matching subtree (`project_tree.rs:389-407,751-797,876-926`); heavily nested roots can revisit an entry for multiple root occurrences and produce multiple logical targets. Neither this review nor the plan claims root-count-independent total projection cost. Sorting also retains normal ordered-container and label-comparison costs.
