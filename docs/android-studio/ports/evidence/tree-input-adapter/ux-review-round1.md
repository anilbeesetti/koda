## Required finding

**P2 — Require actual Directory proof for the module directory before returning a ready tree.**

`crates/android_tools/src/project_tree_adapter.rs:155-156` correctly includes the module directory among required presence paths, but `adapt_captured_module` never validates its effective presence. At `:552-589`, observed descendants may legitimately establish an ancestor directory and explicit presence is checked for contradictions. Neither that code nor the subsequent projection requires the module directory to exist. `project_tree.rs:339-366` validates supported source roots only; `:443-450` permits a missing inventory entry for the module directory, and `:451-463` creates the module row unconditionally.

A fully revision-matched module with no supported roots and empty `entries` therefore succeeds when module-directory presence is omitted/Unknown, explicitly Missing, or explicitly File. The same issue occurs when every supported root is explicitly missing, or existing sources are wholly external and do not establish the module directory. This turns an unavailable or invalid capture into an apparently ready Android module. It violates the owner's stated acceptance contract that module-directory existence must have actual Directory proof and Missing/Unknown/File have typed unavailable outcomes. This finding concerns that capture-boundary contract; it does not assert that the original IntelliJ module object and a filesystem folder are identical concepts.

The new supplemental presentation test already demonstrates the gap at `tests/project_tree_adapter.rs:293-300`: `capture(..., vec![])` explicitly assigns Missing to the module directory through its finite-world helper (`:185-202`), yet `:297` expects a ready module row. Flag this setup as inapplicable to ready-tree acceptance, with the reason retained in task evidence. Preserve the test's display-name/module-identity assertions, supply actual Directory proof in its ready case, and add separate regressions for absent/Unknown, Missing and File module-directory facts. No original reference fixture or assertion should change.

Validate the effective module-directory fact after merging inventory and legitimate observed-descendant directory proof. Accept an observed Directory row, an explicit Directory probe, or a real descendant establishing the module directory. Reject Unknown, Missing and File with a typed reason and the module path. Preserve current contradiction rejection, and cover an external source root that cannot prove module-directory existence. Do not infer existence merely from the Gradle model, the display name, or an arbitrary root-plan path.
